### Краткое описание результата

Небольшое PHP-приложение — менеджер учебных заметок:

- долговременные данные хранятся в JSON-файлах (`data/notes.json`, `data/users.json`);
- имя текущего пользователя и список избранных заметок хранятся в PHP-сессии;
- обработка запроса (контроллер) отделена от шаблона (представление);
- есть простая маршрутизация по параметру `page` и страница 404;
- обрабатываются ошибки чтения/повреждения JSON.

### Используемые технологии

- PHP 8+ (встроенный сервер)
- JSON (file_get_contents + json_decode с JSON_THROW_ON_ERROR)
- PHP Sessions
- Чистый HTML + CSS (без фреймворков)

### Основные сценарии проверки

1. **Список заметок** — данные читаются из `data/notes.json`.
2. **Добавление заметки** — POST → проверка пустого названия → сохранение → redirect (PRG).
3. **Имя пользователя** — сохраняется в `$_SESSION['display_name']`, отображается в шапке. Кнопка «Сбросить» возвращает «Гость».
4. **Избранное** — id заметок хранятся в `$_SESSION['favorites']`, переживают перезагрузку страницы.
5. **Сценарии сессии** — страница `/index.php?page=scenarios` показывает содержимое `session_scenarios.json`. Проверьте в обычной и приватной вкладке.
6. **Ошибка JSON** — временно переименуйте или повредите `notes.json`: пользователь видит понятное сообщение, а не fatal error.
7. **404** — откройте `/index.php?page=unknown` → страница 404.

### Файловое хранилище

- `loadJson()` / `saveJson()` в `src/storage.php` — единственное место работы с файлами.
- `JSON_THROW_ON_ERROR` + проверка существования файла.
- После успешного POST выполняется redirect, чтобы F5 не повторял отправку формы.

**Ограничения подхода:**

- нет конкурентной записи (один пользователь / учебный стенд);
- нет транзакций;
- при росте данных лучше перейти на БД;
- шаблоны пока содержат разметку + минимальную логику отображения (следующий шаг — полноценный View-слой).

### Session

- `session_start()` вызывается один раз в `public/index.php` до любого вывода.
- Имя пользователя и избранное — только состояние UI, сами заметки берутся из JSON.
- В приватном окне сессия всегда новая → имя = «Гость».

### Разделение обработчика и шаблона

- `public/index.php` — принимает запрос, меняет session/данные, готовит массив `$viewData`.
- `render('list', $viewData)` — подключает шаблон и передаёт переменные через `extract()`.
- Шаблон **не** вызывает `file_get_contents` и **не** пишет в `$_SESSION`.

Это прямая подготовка к схеме Router → Controller → Repository → View.

### Dataset

Исходные файлы из задания:

- `notes.json` — список заметок (id, title, done)
- `users.json` — пользователи (id, name)
- `session_scenarios.json` — сценарии проверки сессии

Все три файла реально используются в приложении.

### Контрольные вопросы (краткие ответы)

1. **Входные данные** — `data/notes.json`, `data/users.json`, `data/session_scenarios.json` + POST-формы и session.
2. **Преобразование в интерфейс** — `showList()` готовит данные, `templates/list.php` выводит HTML.
3. **Ошибочное состояние** — отсутствует/повреждён `notes.json`, пустое название заметки.
4. **При росте проекта** — вынести Repository/Controller в классы, добавить роутер, БД, валидацию.
5. **Чистый запуск** — `git clone` → `php -S localhost:8080 -t public`.
6. **PHP vs JS** — PHP выполняется на сервере до отправки HTML; JS — в браузере после загрузки.
7. **Конструктор класса** — полезен для инициализации зависимостей (путь к файлу, настройки) при создании объекта Repository/Controller.
